# 验收与交接

## 文件验证

确认授权主题与写入时点。只讨论时不先写事实；整理已确认资料时不重新询问所有结论。复用责任文档和稳定编号，保留范围外内容。

保存后回读实际文件，逐项比对确认内容。检查相对链接、大小写、目标和必要锚点；路径存在不代表锚点或语义正确。从每条 P0 追到功能、页面入口、里程碑、验收场景，检查断点和依赖环。

报告实际与目标结构、Git、远端、备份、迁移、测试和发布状态，只记实际执行。简短说明文件链接、本轮范围、验证和未决项，按用户要求停下等待，不顺势实现功能。

## “底座完成”的三个层次

| 层面 | 证据 |
| --- | --- |
| 产品与协作 | 责任明确、入口有效、规则唯一、事实与计划确认 |
| 工程 | 实际源码位置、Git/工作树、基线、可运行环境、备份与发布触发 |
| 产品交付 | 固定提交、自检、独立验收、目标环境及用户体验结果 |

## 行为检查场景

1. 空目录、用途未定：只建授权结构，不编造事实或技术栈。
2. 根仓库有未提交内容：先保留盘点，不强制搬 src 或嵌套 init。
3. src 是注册 worktree：识别 .git 文件及 common-dir，不复制成假独立仓库。
4. 旧文档方向与用户冲突：明确指出，按确认结论更新责任文件，保留可复用代码。
5. 最终多场景、本轮单场景：保留长期目标，当前验证核心闭环。
6. mock 通过、目标设备未测：不写全部通过，不自动删除需求。
7. 用户只确认一个阶段：不宣布整份计划通过。
8. main 推送自动部署、只授权本地：指出冲突，不通过推送完成本地整理。
