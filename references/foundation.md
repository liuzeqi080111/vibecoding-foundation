# 结构与协作规则

## 选择最小变更方案

| 现场 | 处理方式 |
| --- | --- |
| 空目录，无仓库 | 按约定创建入口和目录；选择 src 独立仓库时由 Git 初始化 main，不手写 .git |
| 已有根仓库 | 保留历史；若要求 src 独立仓库，先说明迁移影响并确认方案，不直接嵌套初始化 |
| 本目录无 .git，但属于上层仓库 | 检查实际 Git 顶层，不能误判为空项目 |
| 源码在外部或注册 worktree | 实际位置写入实现记录；迁移验证 .git 文件、common-dir、关联路径和活跃任务 |
| 产品转向 | 按确认的新方向分离旧内容，保留历史来源，不把旧产品事实带入新产品 |
| 并行开发 | 读最新交接、核对现场、限定范围，不覆盖、不重复派单、不强制结束其他任务 |

默认结构：

```text
项目根目录/
├── README.md
├── AGENTS.md
├── docs/
│   ├── facts/
│   ├── Spec/
│   └── 工程规则.md
└── src/
    ├── .git/         # 仅在选择独立仓库后由 Git 生成
    └── .gitignore
```

不为迁就结构而迁移已有仓库。空目录不会被 Git 保存，确需同步可用 .gitkeep，不生成空事实。实际路径与目标路径分别描述。

## 入口与规则

README 说明用途（引用确认事实）、目录、文档和源码入口；未知用途写待确认。AGENTS 指向 README、工程规则、事实、实现与最新交接、对应 SPEC，不重复正文。实现记录标时间、提交和证据，历史状态不能写成永久规则。

用户已有规则优先。无既定规则时，可按用户建立基础协作规则的授权采用：

- main 稳定，从确认基线开任务分支开发和自检。
- 实现前确认 SPEC；交付固定提交与自检结果，独立验收针对同一提交。
- 自检和独立验收分开记录；修复后复查受影响部分；通过后按用户授权合并。
- 开发、自检、独立验收、合并职责分清，具体人或 AI 会话由用户确定。
- 合并和上线分开，上线需明确授权；记录实际检查及未验证范围。
- 事实、接口、数据规则变化更新责任文档；先复用组件，不改无关功能。
- 保留证据，清理不再需要的临时文件和服务；验证并合并后再清理分支和工作树。

## Git、迁移与发布

检查 status、branch、worktree list、顶层、远端配置；URL 中凭证脱敏，不输出 .env。禁止用 reset --hard、clean 或强推整理现场。

源码、依赖声明、锁文件、测试、构建运行文件整体考虑。迁移前检查目标冲突和路径边界，保留历史、未提交内容及配置；迁移后验证文件、Git 关联和运行入口。不能直接合并覆盖同名目录。Windows 用单一 shell 的字面路径操作，递归移动/删除前验证绝对路径边界。

.gitignore 按实际栈排除秘密、真实用户数据、缓存、构建和临时文件；保留配置样例和锁文件。忽略规则不会清除已跟踪秘密，发现后另行处理，不声称已安全。

远端沿用核实地址或用户指定目标。上传授权不自动等于公开授权，不擅自更改可见性；未给地址且无创建授权时仅本地准备。推送前检查部署触发，不能将自动部署的 main 推送描述为仅同步。

文档在仓库外时说明备份范围和落实状态，不能声称 src push 已备份 docs。
